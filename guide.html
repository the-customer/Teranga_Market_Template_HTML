Le design est prêt.
À vous de lui donner vie.

Vous disposez d’une maquette complète en HTML et CSS. Votre mission : transformer les écrans en une application Vue conforme aux 24 demandes de la cliente.

Explorer les écrans Ouvrir la boutique

Ce qui est fourni

Des pages statiques, un design responsive, les illustrations locales, les formulaires, les tableaux et leurs variantes d’état.

Les liens HTML et les aperçus CSS permettent d’explorer le design sans installation.

Ce qui est à programmer

Réactivité, événements, validation, filtres, calculs, stores, composants, routage, appels API et persistance.

Aucun code métier JavaScript, aucune connexion API et aucun serveur ne sont fournis dans ce template.

Comment utiliser les fichiers

  1. Décompressez toute l’archive. Ouvrez index.html ou sommaire.html dans le navigateur. Ne déplacez pas une page seule : ses styles et images sont relatifs.
  2. Étudiez le découpage. Les commentaires DEMANDE et les attributs data-component indiquent les responsabilités à extraire.
  3. Créez vos composants Vue. Copiez le balisage utile dans le template d’un composant. Ne recopiez pas doctype, html, head et body dans chaque composant.
  4. Centralisez les ressources. Intégrez les deux feuilles CSS dans le projet Vue. Placez les images dans un emplacement public adapté et ajustez les chemins.
  5. Remplacez les liens de maquette. Les liens entre fichiers deviennent des routes. Les boutons data-action reçoivent vos événements.
  6. Remplacez les constantes par des données. Les cartes répétées deviennent des listes, les montants des propriétés calculées et les variantes des conditions.
  7. Connectez le backend simulé. Construisez votre fichier JSON Server à partir du cahier des charges. Le HTML n’est pas une base de données.
  8. Testez les erreurs autant que le succès. API indisponible, panier vide, prix changé, stock insuffisant et formulaires invalides font partie du projet.

Les conventions du template

data-component="ProductCard"

Nom proposé du futur composant ; il ne produit aucun comportement.

data-action="ajouter-panier"

Point de branchement d’une action JavaScript à écrire.

data-product-id="1"

Identifiant statique de démonstration, à remplacer par une donnée.

--brand / --surface / --ink

Variables CSS communes à toutes les pages.

data-theme="dark"

Variante sombre déjà dessinée. Le changement de thème et sa persistance restent à programmer.

Important : maquette et application ne sont pas équivalentes

Changer une quantité ou un champ ne met aucun total à jour. Les actions Ajouter, Appliquer, Enregistrer, Confirmer et Actualiser sont volontairement inactives.

Les liens vers une confirmation, une carte, un tableau ou un état d’erreur ouvrent des fichiers d’aperçu ; ils ne réalisent pas l’action métier. Les modales et le tiroir utilisent uniquement la cible CSS pour être visibles.

Les formulaires ont des boutons de type button et une validation native désactivée. À l’intégration, gérez leur soumission et leur validation avec Vue et VeeValidate. Le focus automatique, le piégeage du focus et la touche Échap ne sont pas implémentés.

L’administration n’est pas sécurisée. Les noms, coordonnées, prix et commandes sont fictifs. JSON Server reste un backend pédagogique, sans garanties transactionnelles de production.
